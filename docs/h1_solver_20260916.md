# H1 求解耗时优化 · 2026-09-16

本轮优化 WBC 的数值求解过程，保持 MPC 目标、任务权重、接触力锥以及物理约束验收阈值不变。

## 实现

首次创建 OSQP 工作区时，将缩放问题的绝对/相对求解精度设为 `1e-8`，保留 polishing。每次求解成功后，先还原到物理变量，再检查全部线性等式和不等式的绝对违反量是否不超过原有的 `1e-5`。

若首次结果违反物理约束，清除工作区，以 `1e-9` 精度重建并重算一次；达到迭代上限或返回不准确解也使用同一条有界恢复路径。明确不可行或无效结果立即报错。第二次仍不合格则停止，不积分机器人状态。重建后的严格精度随工作区保留，直到再次重建或复位。

`solver_recoveries` 记录以上数值恢复次数，包含物理约束验收失败后的精度细化。这里的求解器精度与物理验收标准是两件事；没有放宽接触、力矩或关节限位。

## 验证

- Python 全量 **339 项通过**，新增测试覆盖“求解成功但违反物理约束”时的重算，以及两次失败后拒绝积分。
- MPC 浏览器循环、暂停、单步、轻推、复位检查通过。
- 带 3 N 周期轻推、5 cm 幅值的 **300 s / 60000 步**长测通过，未发生数值重建或 MPC 连续性回退。最大实际接触约束违反量为零，最大足底漂移约 0.925 µm，最大 WBC 耗时约 53 ms。
- QP 最大绝对约束违反量为 `8.80e-6`，小于不变的 `1e-5` 验收阈值，但高于上一版本约 `8.8e-7` 的观测值；独立正向动力学残差约 `1.94e-12`。数值精度与实际跟踪表现分别记录，不将更宽内部精度称为精度提升。
- 基准脚本新增 `--controller`、`--amplitude`、`--push-force`，支持在同一个带扰动的 MPC 场景下比较。输出包括最大完整计算步耗时、数值恢复次数和实现文件哈希；轨迹最大差取所有重复轮次的最大值。

原始证据：[长测](assets/h1_accuracy_soak.json)、[浏览器](assets/h1_accuracy_browser.json)。

## 同场景性能对比

MPC、5 cm 幅值、周期性 3 N 轻推，每轮 3200 步，新旧实现交替顺序各运行三轮。平均值及 P99 列为三个轮次统计值的中位数，最大值取全部轮次最大值；耗时包含 MPC、WBC、正向动力学和积分，不包含可视化。

| 完整计算步耗时 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 平均 | 2.45 ms | 2.05 ms |
| P99 | 18.43 ms | 15.47 ms |
| 最大 | 50.72 ms | 36.96 ms |

中位总耗时比为 1.19 倍，耗时减少约 16%。最大力矩差约 `1.07e-4 Nm`，配置分量最大差约 `5.14e-11`；测试场景的运动轨迹基本一致。P99 仍超过 5 ms，因此不能保证按 200 Hz 硬实时执行。

完整结果与新旧实现哈希见 [基准 JSON](assets/h1_accuracy_benchmark.json)。以上短轨迹计时与长测最大 WBC 耗时的统计范围不同，不混用。

复现对比时，先从 Git 保存上一版本的动力学实现：

```bash
git show 718a7bf:python/wholebodyx/dynamics.py > /tmp/h1-before-accuracy.py
.venv/bin/python scripts/benchmark_h1_dynamics.py --reference /tmp/h1-before-accuracy.py --controller mpc --amplitude .05 --push-force 3 --steps 3200 --repeats 3 --output /tmp/h1-accuracy-benchmark.json
.venv/bin/python scripts/soak_h1_dynamics.py --controller mpc --push-force 3 --amplitude .05 --seconds 300 --output /tmp/h1-accuracy-soak.json
```

计时取决于机器负载，平均或分位数改善不构成最坏耗时保证。仍然是固定双脚接触的实验性动力学演示，没有实现接触切换、MuJoCo 或动力学行走。

## 后续：自适应更新间隔标定

将 WBC 的 `adaptive_rho_interval` 从 50 调整为 200。它控制 OSQP 每隔多少次内部迭代检查自适应步长，与机器人 5 ms 仿真步长和 MPC 0.1 s 重规划周期无关；算法说明见 [OSQP 官方文档](https://osqp.org/docs/solver/index.html#rho-step-size)。

本次没有改动任务目标、权重、求解精度、物理验收阈值或正向动力学算法。这是对当前 H1 双脚固定接触问题的参数标定，不保证对其他模型或轨迹同样有效。全量 339 项测试与 MPC 浏览器交互检查通过。

新版本在 5 cm 幅值、周期性 3 N 轻推下完成 300 s / 60000 步长测，求解器仅创建一次工作区，没有数值恢复或 MPC 连续性回退。最慢 WBC 步约 29.3 ms；实际接触约束违反量为零，最大 QP 约束违反量 `8.30e-6`，最大足底漂移 0.925 µm。见 [长测 JSON](assets/h1_interval_soak.json) 和 [浏览器结果](assets/h1_interval_browser.json)。

新旧版本交替各跑三轮 3200 步后的完整计算步耗时如下。平均、P95、P99 取三轮各自统计值的中位数，最大值取所有轮次最大值。

| 指标 | 间隔 50 | 间隔 200 |
| --- | ---: | ---: |
| 平均 | 2.05 ms | 1.98 ms |
| P95 | 2.60 ms | 2.65 ms |
| P99 | 15.48 ms | 12.36 ms |
| 最大 | 38.95 ms | 22.36 ms |

本机该场景的 P99 降低约 20%，中位总耗时降低约 3%；P95 略有增加，不是所有分位数都改善。全部轮次均未重建求解器，最大力矩差 `1.74e-4 Nm`、配置分量最大差 `1.12e-10`。结果见 [基准 JSON](assets/h1_interval_benchmark.json)。这些观测仍不满足 5 ms 硬实时要求。
